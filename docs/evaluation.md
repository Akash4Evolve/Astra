# ASTRA detector evaluation (synthetic scenarios)

- Seeds per scenario and parameter: 200 (seeds 0 to 199)
- Parameters: heart_rate, skin_temperature, sleep_hours; 21-day series, baseline = first 14 days
- ASTRA: robust_baseline_v2 + persistence_v1; |robust z| > 3.0 on 2+ consecutive valid readings; low-quality readings never count
- Naive baseline: alert if ANY reading after the baseline window is outside mean +/- k SD of that window (k = 2 and 3); it ignores quality flags
- Data is synthetic and labelled. This is not clinical validation.

## Pooled over all scenarios

| Method | Detection rate | False-alarm rate | Precision |
|---|---|---|---|
| ASTRA | 90.5% | 0.0% | 100.0% |
| Naive +/- 2 SD | 100.0% | 53.1% | 42.9% |
| Naive +/- 3 SD | 99.8% | 36.4% | 52.3% |

Detection rate = alerts on scenarios that contain a real deviation. False-alarm rate = alerts on scenarios that should not alert. Precision depends on the scenario mix (6 negative vs 2 positive types).

## Baseline not established
- missing_data: 12.0% of runs had too few valid baseline samples; alerts are withheld there by design.

## Limits of this evaluation
- heart_rate and skin_temperature use the same noise shape with different units, so their results are identical by construction. They are not independent confirmations.
- Fixed 14-day baseline and 21-day series. Slow drifts need more days to reach REVIEW.
- The naive rule is deliberately simple (spec 9.5). Thresholds in both methods are demo assumptions.
- Synthetic data generated by the team: results show the logic behaves as designed, not that it works on real astronaut data.
